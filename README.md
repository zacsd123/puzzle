# 퍼즐 파티 🧩

사진 한 장을 올리면 퍼즐 조각으로 잘라, 여러 사람이 **실시간으로 함께** 맞출 수 있는 웹 게임입니다.

- 메인 화면에서 **방 만들기 / 방 참여하기** 선택
- 입장할 때는 **이름만** 입력 (초대 링크로 바로 들어와도 이름만 물어봄)
- 모든 참가자의 **마우스 커서가 이름표와 함께 실시간 공유**되고, 누가 어떤 조각을 들고 있는지 색 테두리로 표시
- **조각끼리 이어 붙이기**: 이웃한 조각을 서로 맞는 위치 근처에 놓으면 찰칵 붙어서 한 덩어리가 되고, 이후에는 덩어리째로 함께 움직입니다.
- 조각이나 덩어리를 퍼즐판의 정답 자리 근처에 놓으면 판에 고정됩니다. 판에 고정된 덩어리는 더 이상 움직일 수 없어요.
- 모든 조각이 하나로 이어지면 퍼즐 완성! 진행도는 "남은 덩어리 수"로 표시되고, 참가자별로 **연결 횟수**(붙인 횟수)를 집계합니다. 한 번 내려놓아서 붙으면 1회입니다. (판에 맞춰지면서 이웃과도 붙거나, 한꺼번에 여러 덩어리가 붙어도 1회)
- **방장과 새 퍼즐**: 방을 만든 사람이 방장입니다. 퍼즐을 완성하면 방장에게 "새 사진으로 다시 하기"가 나타나고, 새 사진과 조각 수를 고르면 같은 방의 모든 사람에게 새 퍼즐이 시작됩니다. (연결 횟수는 판마다 0부터) 방장이 방에 없으면 가장 먼저 들어와 있던 사람이 임시 방장이 되고, 방장이 돌아오면 다시 방장이 됩니다. 방장 여부는 방을 만든 브라우저의 식별값으로 서버가 확인합니다.
- **기록 유지**: 방에서 나갔다가 같은 브라우저로 다시 들어오면 연결 횟수와 내 색이 이어집니다. 브라우저에 저장한 식별값(localStorage)으로 알아보며, 쿠키는 쓰지 않습니다. 기록은 방 안에서만 유지되고 서버가 재시작되거나 방이 사라지면 함께 사라집니다. 같은 브라우저의 다른 탭은 따로 참가하고, 같은 탭을 새로고침하면 이전 접속을 대체해서 이어받습니다.
- **커서 채팅** (피그마처럼): `/` 키를 누르면 내 커서 옆에 입력창이 뜨고, 치는 글이 다른 사람 화면의 내 커서 옆에 바로 보입니다. 최대 30자. 마지막으로 글을 고친 뒤 3초는 또렷하게, 이어서 5초 동안 서서히 사라집니다. `Enter`는 지금까지 쓴 글을 지우고 새로 쓰기, `Esc`는 닫기입니다.
- 다른 사람이 들고 있는 덩어리는 잡을 수 없고, 그 덩어리와는 붙지도 않습니다. (놓는 순간 붙을 수 있으면 그때 붙음)
- 줌(휠) / 화면 이동(빈 곳 드래그) / 원본 힌트 보기

## 기술

React + TypeScript (Vite) 화면, Node + TypeScript 서버(`ws` WebSocket). 서버 하나가 화면과 WebSocket을 모두 서비스합니다.

```
src/      React 화면 (페이지, 캔버스 렌더러, 접속/상태 관리)
server/   HTTP API(이미지 업로드) + WebSocket 게임 서버
shared/   서버·화면이 같이 쓰는 메시지 타입
```

## 실행

처음 한 번:

```bash
npm install
```

**개발 (코드 수정이 바로 반영됨)** — 화면 `http://localhost:5199`, 서버 `3001`

```bash
npm run dev
```

**실제 운영 (맥미니/데스크탑에서 켜두는 방식)** — 한 포트(기본 `3001`)로 모두 제공

```bash
npm run build
npm start
```

서버를 켜면 접속 주소가 출력됩니다. 같은 와이파이의 다른 기기에서는 출력된 `http://192.168.x.x:3001` 로 접속하면 됩니다.

포트는 `PUZZLE_PORT=8080 npm start` 처럼 바꿀 수 있습니다.

## 인터넷의 친구와 함께 하려면

같은 와이파이 밖의 사람이 접속하려면 내 컴퓨터를 인터넷에 노출해야 합니다. 쉬운 순서대로:

1. **Cloudflare Tunnel** (`cloudflared tunnel --url http://localhost:3001`) — 공유기 설정 없이 임시 `https://...` 주소를 줍니다.
2. **Tailscale** — 친구들도 Tailscale에 초대하면 사설망처럼 접속할 수 있습니다.
3. **공유기 포트포워딩** — 3001 포트를 이 컴퓨터로 열어주고 공인 IP로 접속. (HTTPS 없이 노출되니 주의)

> 방은 서버 메모리에만 저장됩니다. 서버를 재시작하면 방과 진행 상황이 사라지고, 아무도 없는 방은 6시간 뒤 자동 삭제됩니다.

## 프론트/백엔드 분리 배포 (집 컴퓨터 안 켜놔도 되는 방식)

프론트는 Vercel 같은 정적 호스팅에, 백엔드는 Render 같은 Node 호스팅에 따로 올리는 방법입니다. 계속 켜둘 집 컴퓨터가 필요 없고, 안정적인 고정 주소가 생깁니다.

**백엔드 (Render)**

1. 이 저장소를 GitHub에 올리고, Render에서 "New > Blueprint"로 연결하면 저장소에 있는 [render.yaml](render.yaml)을 읽어 자동으로 설정됩니다.
2. 배포되면 `https://puzzle-party-server.onrender.com` 같은 주소가 생깁니다. 이게 백엔드 주소입니다.
3. Render 대시보드 환경변수에서 `ALLOWED_ORIGIN`을 프론트 주소(예: `https://your-app.vercel.app`)로 바꿔주면 그 도메인만 API를 호출할 수 있습니다. (안 바꾸면 전체 허용 `*`로 동작, 테스트용으로는 괜찮음)
4. 무료 플랜은 트래픽 없으면 잠들었다가 첫 요청에 깨어나서 몇십 초 걸릴 수 있습니다.

**프론트 (Vercel)**

1. Vercel에서 같은 저장소를 Import, 빌드 커맨드는 기본값(`npm run build` → `dist/`) 그대로 두면 됩니다.
2. Vercel 프로젝트 환경변수에 `VITE_API_URL`을 백엔드 주소로 설정합니다 (예: `https://puzzle-party-server.onrender.com`). 이 값이 있으면 프론트가 API/이미지/WebSocket을 전부 이 주소로 호출합니다. 자세한 값은 [.env.example](.env.example) 참고.
3. 배포 후 Render 쪽 `ALLOWED_ORIGIN`을 이 Vercel 주소로 맞춰줍니다.

`VITE_API_URL`을 비워두면 지금까지처럼 프론트와 백엔드가 같은 origin이라고 가정하고 동작합니다 (한 서버로 `npm start` 하는 기존 방식).

## 제한

- 사진은 업로드 전에 브라우저에서 JPEG로 줄여서 올립니다. 긴 변은 조각 300개 이하면 1600px, 그보다 많으면 2400px 이하입니다 (서버 최대 8MB).
- 조각 수는 방 만들기 화면의 슬라이더로 고릅니다. 10~100개는 10개 단위, 150~1000개는 50개 단위예요. 실제 조각 수는 사진 비율에 맞춰 약간 달라질 수 있고(예: 1000 → 988), 최대 1000개입니다. (`shared/protocol.ts`의 `MAX_PIECES`)
- 방당 최대 20명, 동시에 최대 100개 방.
- 붙는 거리 기준은 조각 짧은 변의 30%입니다. (`shared/protocol.ts`의 `SNAP_RATIO`로 조절)
